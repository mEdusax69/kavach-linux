# Kavach Linux 1.0 "Rakshak" — Documentation

A minimal, from-scratch **live Linux distribution** that boots entirely into RAM from an ISO. It is console-only, tiny (~29 MB), and ships with a few built-in helper tools for disk inspection and file hashing.

| Item | Value |
|---|---|
| Name / version | Kavach Linux 1.0 (codename *Rakshak*) |
| ISO file | `kavach-linux-1.0.iso` (~29 MB) |
| SHA-256 | `3d56ff3b23451479cc8601f3cbcef0f3579b06eab396e6e16cef0edbbeaa9fea` |
| Architecture | x86_64 |
| Boot modes | BIOS (legacy) and UEFI, hybrid ISO (CD/DVD or USB) |
| Kernel | Linux 6.8.0-146-generic (stock Ubuntu 24.04 kernel) |
| Userland | BusyBox 1.36.1 (static) — shell, coreutils, networking, editors (vi) |
| Bootloader | GRUB 2 |
| Init | BusyBox init (`/etc/inittab`) |
| Persistence | None — everything runs from RAM, changes are lost on reboot |

## 1. Architecture

```
  Firmware (BIOS/UEFI)
        │
        ▼
     GRUB 2  ──loads──►  /boot/vmlinuz  +  /boot/initrd.img
                                  │
                                  ▼
                   Linux kernel unpacks initrd into RAM (rootfs)
                                  │
                                  ▼
                    /init → BusyBox init → /etc/init.d/rcS
                                  │
            mounts /proc /sys /dev, loads drivers, starts DHCP
                                  │
                                  ▼
                     getty on tty1–tty3 (+ serial) → login → sh
```

The whole root filesystem lives inside the compressed initramfs (`initrd.img`), so the ISO needs no CD-ROM driver after GRUB has loaded it. This is why it works on almost any machine or VM.

### ISO layout
```
/boot/vmlinuz            Linux kernel
/boot/initrd.img         gzip-compressed cpio archive = the entire OS
/boot/grub/grub.cfg      boot menu
(+ GRUB BIOS/EFI images generated by grub-mkrescue)
```

### Root filesystem layout (inside initrd.img)
| Path | Purpose |
|---|---|
| `/bin` | BusyBox binary + ~270 applet symlinks |
| `/sbin/init` | symlink to BusyBox init (`/init` points to it) |
| `/etc/inittab` | what init runs: boot script, gettys, shutdown |
| `/etc/init.d/rcS` | boot script: mounts, driver loading, networking |
| `/etc/os-release`, `/etc/motd` | distro identity and login banner |
| `/usr/bin/kavach` | the built-in helper tool |
| `/usr/share/udhcpc/default.script` | applies DHCP lease (IP, route, DNS) |
| `/lib/modules/6.8.0-146-generic` | 27 curated kernel modules (USB, SATA/NVMe, NICs, filesystems) |

## 2. Running it

### In a virtual machine (easiest)
**QEMU:**
```bash
qemu-system-x86_64 -m 512 -cdrom kavach-linux-1.0.iso -boot d
```
**VirtualBox / VMware:** create a new Linux (64-bit) VM, 256 MB+ RAM, no hard disk needed, attach the ISO as the optical drive and boot.

> For UEFI in QEMU add `-bios /usr/share/ovmf/OVMF.fd`.

### On real hardware (USB stick)
> ⚠️ This **erases** the target device. Double-check the device name with `lsblk`.
```bash
sudo dd if=kavach-linux-1.0.iso of=/dev/sdX bs=4M status=progress conv=fsync
```
On Windows use Rufus (choose *DD Image mode*) or balenaEtcher.

### Minimum requirements
x86_64 CPU, **256 MB RAM** (512 MB recommended), keyboard and display. A network card is optional.

### Logging in
Two accounts exist, both with **no password** (live-session convenience):
- `root`
- `kavach` (uid 1000)

Switch virtual consoles with **Alt+F1 / F2 / F3**.

## 3. Built-in tools: the `kavach` command

| Command | What it does |
|---|---|
| `kavach info` | Distro name, kernel, uptime, memory |
| `kavach hash <file>` | MD5, SHA-1 and SHA-256 of a file |
| `kavach hexview <file\|dev> [n]` | Hex dump of the first *n* bytes (default 256) |
| `kavach disks` | List block devices and partitions |
| `kavach image <src> <dst>` | Raw copy (`dd`, skips read errors) then prints SHA-256 of the image |
| `kavach mountro <dev> [dir]` | Mount a device **read-only** with `ro,noexec,nosuid,nodev` |
| `kavach net` | Interfaces, routes, DNS |
| `kavach strings <file> [min]` | Printable strings extracted from a file |

Example session:
```
# kavach disks
# kavach mountro /dev/sda1 /mnt
# kavach hash /mnt/some-file.bin
# kavach image /dev/sda1 /tmp/sda1.img
```
BusyBox also provides the usual tools: `ls cat grep sed awk find tar gzip dd fdisk mount ping wget vi ps top ip nc telnet` and more (run `busybox --list`).

## 4. Networking
At boot every network interface is brought up and `udhcpc` requests a DHCP lease in the background. The default script sets the IP address, default route and `/etc/resolv.conf`. Check with `kavach net`. Static setup example:
```
ip addr add 192.168.1.50/24 dev eth0
ip route add default via 192.168.1.1
echo "nameserver 1.1.1.1" > /etc/resolv.conf
```
Wi-Fi is **not** supported in 1.0 (no wireless firmware/tools included).

---

## 5. Hardware support
Built into the kernel: PS/2 keyboard/mouse, VGA/framebuffer text console, most core storage and virtio devices. Loaded as modules at boot (by hardware-ID matching): USB 1/2/3 host controllers, USB HID and mass storage, AHCI/SATA, NVMe, Intel e1000/e1000e/igb, Realtek r8169/8139, virtio block/net/GPU, plus filesystems vfat, exFAT, NTFS (ntfs3), ext4, ISO9660 and squashfs.

Graphics are text-mode only (no X11/Wayland).

## 6. Rebuilding the ISO yourself
The included `build.sh` reproduces the whole ISO on Ubuntu 24.04.

**Prerequisites**
```bash
sudo apt install xorriso grub-pc-bin grub-efi-amd64-bin mtools cpio busybox-static zstd kmod
mkdir -p build/kdl && cd build/kdl
apt-get download linux-image-6.8.0-146-generic linux-modules-6.8.0-146-generic
mkdir ex && for f in *.deb; do dpkg-deb -x $f ex; done
depmod -b ex 6.8.0-146-generic
```
Adjust the `SRC`, `W` and `OUT` paths at the top of `build.sh`, then run it as root. (The kernel package version may have moved on; update `KVER` to match.)

**What the script does:** (1) creates the directory skeleton, (2) installs BusyBox and symlinks every applet, (3) resolves and decompresses the chosen kernel modules and runs `depmod`, (4) writes config files, init scripts and the `kavach` tool, (5) packs everything into `initrd.img` with `cpio` + `gzip`, (6) writes `grub.cfg` and builds the hybrid BIOS/UEFI ISO with `grub-mkrescue`.

### Customising
- **Add a command:** drop an executable script in `/usr/bin` inside the build script.
- **Add a program:** copy a *statically linked* binary into `/usr/bin` (or the libraries it needs).
- **Add drivers:** append module names to the `MODS` list.
- **Change branding:** edit `/etc/os-release`, `/etc/motd`, and the GRUB menu titles.
- **Set a password:** put a hash from `openssl passwd -6` in the second field of `/etc/passwd`.

## 7. Testing performed
Booted in QEMU (BIOS, 512 MB RAM, e1000 NIC): GRUB menu → kernel → login prompt; `/etc/os-release` correct; DHCP lease obtained (10.0.2.15, default route, DNS); `kavach info`, `hash`, `net` and `disks` all work. **Not tested:** UEFI boot, real hardware, USB boot.

## 8. Known limitations
- No persistence, no installer — it is a live system only.
- No Wi-Fi, no GUI, no package manager.
- No-password logins are meant for offline/lab use; don't expose it to untrusted networks as-is.
- The kernel and BusyBox are unmodified Ubuntu builds, so Kavach is a custom *assembly*, not a new kernel or from-source toolchain.
